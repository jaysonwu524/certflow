# 证书生命周期与自动化

本页描述 CertFlow 当前面向操作者的证书工作流。数据模型、幂等和 API 细节以 [架构概览](../architecture/overview.md) 为准。

## 域名与通配符

一张证书可包含多个 SAN。通配符遵循 X.509 语义：`*.example.com` 只覆盖一层子域，不覆盖 `example.com`，也不覆盖 `v1.api.example.com`。

若需要覆盖根域、一层子域和特定二层子域，应在同一证书中申请：

```text
example.com
*.example.com
*.api.example.com
```

所有通配符必须使用 DNS-01 验证。

## 签发与验证

创建证书时选择 ACME 账户、域名、密钥算法与验证方式：

- 自动 DNS：CertFlow 使用所选 DNS 账户写入并清理 `_acme-challenge` TXT 记录。已有相同 TXT 值会复用，不会重复创建。
- 手动 DNS：CertFlow 保存 ACME 订单和 TXT 值，执行记录进入 `waiting_user`；操作者完成 DNS 写入后在控制台继续验证。手动记录不会被 CertFlow 删除。

新签发和续期都会产生不可变证书版本。私钥、证书和链以密文保存，API 与界面不回显私钥。

## 自动化任务

自动化页面提供三种任务：

| 类型 | 输入 | 行为 |
| --- | --- | --- |
| 证书续期 | 证书、续期窗口、启停状态 | 调度器扫描即将到期的已签发证书并排队续期。 |
| 上传 SSL 证书管理 | 证书、云凭证 | 将当前证书版本上传到阿里云 SSL 证书管理。 |
| ALB 配置更新 | 证书、云凭证、地域、ALB、监听器 | 上传证书并更新 HTTPS/QUIC 监听器的默认证书。 |

创建自动化任务只保存配置，不会立即触发外部云操作。操作者可手动执行，续期任务则由调度器在符合条件时执行。

同一证书版本与监听器的重复部署会按幂等边界合并；每次执行都保存执行记录、步骤摘要与脱敏错误。

## 通知与状态

浏览器通过 SSE 接收按权限过滤的状态事件。数据库和 REST API 是状态真相，SSE 仅用于及时呈现。

失败事件可通过站内信、SMTP 邮件和个人 Webhook 投递。外部通知不会阻塞签发或部署 worker。
